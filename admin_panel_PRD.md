# Панель администратора кофейни «Долина Кофе» — PRD

**Формат:** PWA (тот же стек и дизайн, что и mini-app лояльности: React + TS + Tailwind, Montserrat, чёрно-белый, тени `.tap`).
**Цель:** данные о клиентах, удобное представление, автоформирование задач для менеджера по повышению лояльности. Автоматизация службы заботы о клиенте.
**Домен:** поддомен/путь на том же сервере (напр. `dolina-coffee.ru/admin` или `admin.dolina-coffee.ru`). Отдельное приложение от гостевого mini-app.

---

## Исходные требования (от заказчика)

1. Защищённая авторизация (логин+пароль).
2. Экран «Задания» — клиенты с просевшими за неделю метриками, по когортам:
   - **5+ визитов / 30 дней:** таблица (имя, телефон, какая метрика упала, галочка «выполнено»).
   - **2–4 визита / 30 дней:** таблица.
   - **1 визит / 30 дней:** без детализации по гостю — если ключевые метрики просели, одна общая задача («найти +5 блогеров на этой неделе») + галочка.
3. Экран «Аналитика» — данные за календарную неделю: таблица + столбчатые графики (сравнение с прошлыми неделями). Шаблон: `docs/analytics-template.png`.
4. Выбор периода (список календарных недель).
5. Отчёт по выполнению задач: % по когортам за каждую неделю + список «обделённых вниманием» (задача не выполнена).
6. Выгрузка задач: копировать текстом в буфер / поделиться / Excel.
7. Выгрузка аналитики в Excel.
8. Заморозка статуса: галочки можно ставить только на задачах текущей недели (на основе данных прошлой недели).
9. Отображение роли вошедшего.
10. В прошлых неделях у выполненной задачи — имя+фамилия исполнителя.

---

## Согласованные решения

- **Авторизация:** своя (бэкенд + БД). Пользователи, роли, пароли — у себя (хеш пароля bcrypt, JWT-сессия). Роли: `admin`, `manager`.
- **Источник данных о гостях:** из iiko по API. iiko НЕ отдаёт «всех гостей списком», поэтому база гостей **реконструируется из заказов** (заказы содержат гостя) + `customer/info` по телефону для деталей.
- **Сбор данных:** фоновый сбор **раз в сутки** (ночью, cron). Бэкенд выгружает заказы из iiko за день → агрегирует по гостю → пишет недельные снимки метрик в БД. Панель читает из БД (быстро, историчность).
- **Метрики (из шаблона аналитики):** число **гостей** и число **чеков** по сегментам частоты визитов; плюс **средний чек** для графиков. Сегменты: `7+, 6, 5, 4, 3, 2, 1`.
- **Графики:** на каждый сегмент — **3 графика** (гости / чеки / средний чек). Каждый график = 6 столбцов: текущая неделя (ярко-синий `#0077FF`) + 5 прошлых недель (серый). Итого 7 сегментов × 3 = 21 график (компактные спарклайны/мини-бары).
- **Экспорт:** настоящий **.xlsx** (библиотека `exceljs`) — и для аналитики, и для задач. Плюс задачи — копирование текстом и Web Share API.

## Модель данных (БД: SQLite через better-sqlite3, на volume; при росте → Postgres)

```
users            id, login, passwordHash, name, surname, role(admin|manager), createdAt
sessions         (JWT stateless; либо таблица refresh-токенов)

guests           iikoId (PK), phone, name, surname, firstSeen, lastSeen
                 -- реконструируются из заказов

orders_daily     -- сырьё сбора: агрегат по гостю за день
                 date(YYYY-MM-DD), guestIikoId, ordersCount, ordersSum
                 PK(date, guestIikoId)

week_guest       -- снимок метрик гостя за календарную неделю (ISO-неделя)
                 weekStart(YYYY-MM-DD, понедельник), guestIikoId,
                 visits30d, ordersCount, ordersSum, segment(1..7),
                 -- сравнение с прошлой неделей заполняется при чтении
                 PK(weekStart, guestIikoId)

week_segment     -- агрегат аналитики по сегменту за неделю (для экрана 2 и графиков)
                 weekStart, segment(1..7|'total'),
                 guests, checks, sum
                 PK(weekStart, segment)

tasks            id, weekStart, cohort('5plus'|'2-4'|'1'),
                 guestIikoId(nullable для когорты «1»),
                 reason(текст: какая метрика упала),
                 done(bool), doneByUserId(nullable), doneByName(nullable), doneAt
                 -- генерируются при закрытии недели по правилам просадки
```

**ISO-неделя:** неделя = Пн–Вс. `weekStart` — дата понедельника (ключ периода).

## Сбор данных из iiko — РЕАЛЬНОСТЬ (проверено на ключе 2026-07-22)

**Проверка живого API показала:**
- `deliveries/by_delivery_date_and_status` → **0 заказов** (кофейня на POS/столах, доставки нет). Не подходит.
- OLAP-отчёты (`reports/olap/*`, список всех заказов/гостей) → **401**, доступа нет.
- Заказы на столах через Transport нельзя перечислить за период (только по tableId, только открытые).

**Вывод — база гостей строится через ВЕБХУКИ (единственный путь для POS):**
- `POST /api/1/webhooks/update_settings` — включить `TableOrderUpdate` (и `DeliveryOrderUpdate` на будущее) на наш `webHooksUri` (уже есть `POST /api/webhooks/iiko`).
- Каждый закрытый чек прилетает вебхуком → извлекаем гостя (customer.phone/id) + сумму чека → пишем в `orders_daily`, обновляем `guests`.
- База и метрики копятся **вперёд, со дня подключения вебхука**. Исторических данных (5–6 недель назад) не будет, пока не накопим — графики заполнятся за ~6 недель. Бэкфилл возможен только при доступе к OLAP/RMS (сейчас нет) — уточнить у iiko при необходимости.
- Детали гостя (имя/телефон) при необходимости дополняем через `customer/info`.
- Сверка недельных чисел — через `get_counters` (period=Week, metric OrdersCount/OrdersSum).

**Пайплайн:**
1. **Онлайн (вебхук):** на каждый закрытый чек — upsert в `orders_daily` (по гостю: +1 чек, +сумма), обновить `guests`.
2. **Ночью (cron):** нормализация за прошедший день (дедуп по orderId), пересчёт.
3. **В ночь понедельника (закрытие недели):**
   - для каждого гостя посчитать `visits30d`, `ordersCount`/`ordersSum` за неделю → сегмент → `week_guest`.
   - агрегировать по сегментам → `week_segment`.
   - сгенерировать `tasks` за прошедшую неделю по правилам просадки (сравнение с позапрошлой).

> **Зависимость:** для старта сбора нужно прописать вебхук `TableOrderUpdate` в iiko (Настройки Cloud API → интеграция → Webhooks, URL `https://dolina-coffee.ru/api/webhooks/iiko`). Точный формат `eventInfo` закрытого чека снимем с первого реального события в логах и подгоним маппинг.

**Правила задач (просадка неделя-к-неделе):**
- Когорта **5+** и **2–4:** гость попал в задачу, если его метрики (визиты/сумма) за прошлую неделю ниже, чем за позапрошлую (или упал сегмент). reason = что именно упало.
- Когорта **1:** без персон. Если суммарные метрики сегмента «1» просели → одна общая задача «Найти +5 блогеров».
- Точные пороги просадки — параметр (по умолчанию любое снижение; вынести в конфиг).

## Экраны (PWA, дизайн mini-app) — детальная спецификация

**Акцентный цвет — ярко-синий `#0077FF`** (отличие от чёрно-белого гостевого mini-app).

**Навигация (общая, на всех страницах):**
- Сверху: логотип «Долина Кофе» + аватар пользователя (как в основном приложении).
- Переключатель (toggle) как в mini-app, но с другими иконками — переключает Задания ⇄ Аналитика.
- Аватар → профиль пользователя (роль, имя, выход).

**Логин** — логин+пароль, ошибка, «запомнить». После входа роль видна в шапке/профиле.

**Экран 1 «Задания»:**
- Под навигацией — горизонтальный **скролл-бар выбора недели**. Недели = квадраты с **номером недели в году**.
  - Активная (выбранная) неделя — сплошной акцент `#0077FF`, белый текст.
  - Прошлые недели с данными — серые с тёмным (контрастным) текстом.
  - Будущие недели — светло-серые, неконтрастные к фону.
  - Скролл к прошлой неделе делает её акцентной, а бывшая активная возвращается в обычный серый. Акцент = неделя, за которую показываем данные.
- Далее задания по сегментам в порядке: **5+**, затем **2–4**, затем **1**.
  - У каждого задания — **чекбокс** отметки выполнения.
- Внизу — кнопка **«Подтвердить выполнение заданий»**:
  - активна только когда **все** чекбоксы недели отмечены;
  - по нажатию неделя получает статус **«100%»** (до подтверждения статус не начисляется, даже если галочки стоят).
  - Заморозка: отмечать/подтверждать можно только неделю на основе прошлых данных (текущую рабочую неделю).

**Экран 1 «Задания»** (текущая неделя, на основе прошлой):
- Три секции-когорты (5+, 2–4, 1).
- 5+/2–4: таблица `имя · телефон · что упало · [✓]`. Чекбокс активен только для текущей недели (заморозка). Отметка → пишем doneByName (имя+фамилия вошедшего) + doneAt.
- 1: карточка с общей задачей + один чекбокс.
- Кнопки: «Скопировать текстом», «Поделиться» (Web Share), «Excel».

**Экран 2 «Аналитика»** (по выбранной неделе):
- Таблица как в шаблоне: Сегмент · Прошлая нед. гостей/чеков · Текущая гостей/чеков · Динамика гостей(шт,%) · Динамика чеков(шт,%) · Итого.
- Авто-вывод под таблицей («по гостям −X%, по чекам −Y%…»).
- Блок графиков: на каждый сегмент 3 мини-бар-чарта (гости/чеки/ср.чек) × 6 недель (текущая синяя, прошлые серые).
- Кнопка «Excel».

**Выбор периода** — выпадающий список календарных недель (из `week_segment`).

**Экран «Отчёт по задачам»** — по неделям: % выполнения на когорту + список необработанных клиентов; за прошлые недели видно, кто выполнил (имя+фамилия).

## Бэкенд (расширение существующего `server/`)

Новые роуты под `/api/admin/*` (JWT-guard, роль):
- `POST /api/admin/login` → { token, user{name,surname,role} }
- `GET  /api/admin/tasks?week=` → когорты с задачами
- `POST /api/admin/tasks/:id/done` → отметить (только текущая неделя)
- `GET  /api/admin/analytics?week=` → таблица сегментов + серии для графиков (6 недель)
- `GET  /api/admin/weeks` → список недель
- `GET  /api/admin/report?week=` → сводка выполнения
- `GET  /api/admin/export/analytics.xlsx?week=` / `GET /api/admin/export/tasks.xlsx?week=`
- Cron-задача сбора (node-cron) внутри контейнера API.

Зависимости: `better-sqlite3`, `bcryptjs`, `jsonwebtoken`, `exceljs`, `node-cron`.

## Порядок сборки (многосессионно)

1. **БД + миграции + сбор из iiko** (orders_daily → week_guest → week_segment), cron. Сверка на реальных данных.
2. **Авторизация** (users, login, JWT, роли, гуард).
3. **Экран Аналитика** (таблица + графики + выбор недели + xlsx).
4. **Экран Задания** (генерация задач, чекбоксы с заморозкой, экспорт текст/share/xlsx).
5. **Отчёт по задачам** (проценты, обделённые, исполнители).
6. Полировка, роли в шапке, PWA-манифест админки.

## Открытые вопросы / риски

- **Полнота заказов из iiko:** окна ретрива (7/90 дней). Для первичного заполнения истории (5–6 недель назад) — разовый бэкфилл через `deliveries/history/by_delivery_date_and_phone` или OLAP, если доступен. Проверить на реальном ключе.
- **«Визиты» = число заказов** (чеков) гостя. Уточнить, если «визит» ≠ «чек».
- Первые 5–6 недель графиков будут неполными, пока не накопится история.
