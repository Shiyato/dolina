# Dolina Coffee — программа лояльности

PWA-приложение программы лояльности сети кофеен **Dolina Coffee**. Гость
авторизуется через **VK ID**, показывает **QR-код** на кассе, копит и списывает
**бонусы**. Учёт бонусов и данные гостя — на стороне **iiko** (iikoCloud API).

- **Рабочий домен:** https://dolina-coffee.ru
- **Формат:** PWA (устанавливается на домашний экран, работает как приложение)
- **Платформа лояльности:** iiko (тариф **Pro** — нужен iikoCard + доступ к API)

---

## 1. Продуктовая концепция

Приложение — это «цифровая карта лояльности в кармане». Гостю не нужно ставить
приложение из стора и регистрироваться заново: он входит через VK ID в один тап,
и система по его номеру телефона находит карту в iiko.

**Ключевой принцип:** приложение **не является источником истины** по бонусам.
Баллы считает касса (iikoCard). Приложение только **показывает** баланс/QR и
**инициирует** списание — фактический расчёт скидки идёт на POS.

### Пользовательские сценарии

1. **Первый вход.** Гость открывает `dolina-coffee.ru` → «Войти через VK ID» →
   VK возвращает номер телефона (scope `phone`) → по номеру ищем гостя в iiko.
   - Гость найден → показываем карту (QR + баланс).
   - Гость **не найден** → экран «Вы не зарегистрированы в системе лояльности,
     чтобы продолжить — прийдите в кофейню Dolina Coffee». (Регистрация карты
     происходит офлайн на кассе, приложение её не создаёт.)
2. **Показ на кассе.** Гость открывает главный экран → кассир сканирует QR
   (в QR зашит номер карты / `card track`) → iiko начисляет/списывает бонусы.
3. **Профиль.** Гость смотрит историю начислений и списаний баллов.

## 2. Архитектура

```
┌─────────────────────┐      VK ID (phone scope)     ┌──────────────┐
│   PWA (этот репо)    │ ───────────────────────────▶ │   VK ID      │
│  React + TS + TW     │ ◀─── code + device_id ────── │  OAuth/PKCE  │
└─────────┬───────────┘                               └──────────────┘
          │  HTTPS (свой API)
          ▼
┌─────────────────────┐   exchange code → phone      ┌──────────────┐
│   Backend (позже)   │ ───────────────────────────▶ │  VK API      │
│  Node/Go/...        │                               └──────────────┘
│  - VK code exchange │   customer/info по телефону   ┌──────────────┐
│  - iiko proxy       │ ───────────────────────────▶ │ iikoCloud API│
│  - журнал операций  │ ◀── баланс, карта, кошельки ─ │ api-ru.iiko  │
└─────────────────────┘                               │  .services   │
                                                      └──────────────┘
```

**Почему нужен backend, а не «фронт напрямую в iiko/VK»:**
- Обмен VK `code → access_token → phone` и `api_login` iiko нельзя держать
  в браузере (утечёт секрет).
- История операций в iikoCloud API **отдельным методом не отдаётся** — её надо
  собирать самим из вебхуков и хранить в своей БД.

> **Статус:** backend разрабатывается позже. Сейчас фронт работает через
> **мок-слой** (`src/services/`) с чётким сеймом — реальный API подменяется
> заменой реализации в одном месте (`iiko.ts`, `vk.ts`), без правок экранов.

### Слои фронтенда

| Слой | Файлы | Назначение |
|------|-------|-----------|
| Экраны | `src/screens/` | Auth, Card (QR+баллы), Profile (история) |
| Навигация/гард | `src/App.tsx`, `src/auth/` | роутинг + защита приватных экранов |
| Сервисы | `src/services/` | VK, iiko, типы, мок-данные (сейм для backend) |
| UI-кит | `src/components/` | переиспользуемые элементы, токены в `index.css` |

## 3. Авторизация (VK ID)

**Конфигурация** (из `vk_auth.html`):
- `app: 54684617`
- `redirectUrl: https://dolina-coffee.ru`
- `responseMode: Callback`
- `scope: phone` — обязателен, номер телефона нужен как ключ к iiko.

**Поток (реализовано, клиентский PKCE):**
1. VKID OneTap (виджет) → `LOGIN_SUCCESS` → `{ code, device_id }`.
2. `VKIDSDK.Auth.exchangeCode(code, device_id)` → access token **в браузере**
   (PKCE, секрет клиента не нужен — публичный клиент).
3. `VKIDSDK.Auth.userInfo(token)` → телефон + имя + аватар (`photo_200`).
4. Телефон → `iiko.getCustomerByPhone()` → гость или `null`.
5. Гость есть → сессия в `localStorage` + Card; нет → экран «не зарегистрирован».

Реализация: `src/services/vk.ts` (`renderOneTap`, `exchangeCode`, извлечение
профиля), `src/auth/AuthContext.tsx` (`loginWithProfile`). Аватар из VK
приоритетнее (iiko аватар не отдаёт) и сохраняется в сессии.

**Режимы:** `VK_ENABLED` = прод → реальный VK, dev → мок (`vk.mockLogin`).
Переопределяется `VITE_VK_MODE=real|mock`. На localhost реальный VK не работает
(CORS к `id.vk.ru` — домен не авторизован), поэтому в dev по умолчанию мок.

**Требования к VK-приложению `54684617`:** домен `dolina-coffee.ru` в доверенных
redirect/доменах (совпадает с `redirectUrl`), **включён scope `phone`**. Без
phone-scope VK не отдаст телефон — вход завершится ошибкой «VK не передал номер».

**Что ещё уйдёт на backend (позже):** обмен `code` можно перенести на сервер для
доп. безопасности; поиск гостя в iiko (`customer/info`) и `wallet/*` — обязательно
на backend (там секретный `api_login`). Сейчас iiko — мок.

Сессия хранится в `localStorage` (ключ `dolina.session`). Реальный вариант —
httpOnly-кука от backend.

## 4. Интеграция с iiko (iikoCloud API, `api-ru.iiko.services`)

| Функция | Метод | Статус |
|---------|-------|--------|
| Данные гостя + баланс | `POST /api/1/loyalty/iiko/customer/info` (по телефону) | ✅ штатно, поле `walletBalances[]` |
| Начисление/списание | `wallet/topup`, `wallet/chargeoff`, `wallet/hold` | ✅ штатно |
| Расчёт скидок в заказе | `POST /api/1/loyalty/iiko/calculate` | ✅ штатно |
| **История операций** | — | ⚠️ прямого метода нет |

**История начислений/списаний** (экран Профиль) собирается на backend:
подписка на вебхуки (`/api/1/webhooks/settings`), по закрытию чека пишем в свою
БД `{ дата, заказ, сумма, начислено, списано }`. Экран Профиль читает историю из
нашей БД, а текущий баланс сверяется через `customer/info` (iiko — источник истины).

Типы кошельков iiko: `0` депозит · `1` бонусная программа · `2` продуктовая ·
`3` скидочная · `4` сертификаты. Для карты используем `type: 1`.

### 5.2 Главный экран — карта (`CardScreen`)
Экран из Figma (node `3:3247`): аватар · переключатель QR/бонусы · логотип,
крупный баланс баллов, QR-код, подсказка, строка кэшбека. Тап по аватару → Профиль.

### 5.3 Профиль — история (`ProfileScreen`)
Список операций начисления/списания баллов (из Figma). Данные — из журнала
backend (сейчас мок). Группировка по датам, у каждой операции: тип, заведение,
сумма чека, ±баллы.

## 6. PWA

- `manifest.webmanifest` — имя, иконки, `display: standalone`, тема бренда.

## 7. Стек и запуск

- **React 18 + TypeScript + Tailwind CSS v4**, сборка **Vite**.
- Шрифт **Montserrat** (баланс/акценты) + системный **SF Pro** (текст).

```bash
npm install
npm run dev      # локальная разработка
npm run build    # прод-сборка в dist/
```

Дизайн-токены — в `src/index.css` (`@theme`), значения из Figma-переменных:
`#007AFF` (VK/iOS blue), `#707579` (muted), `#EFEFF4` (secondary bg) и т.д.
